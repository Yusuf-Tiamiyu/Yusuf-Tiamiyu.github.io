No central view of anything

Built for a multi-site diagnostic laboratory. All data shown here has been anonymised. Site names, staff counts, and test volumes are real but identifying details have been removed.

Before this dashboard existed, getting a network-wide view of lab performance meant calling each site individually, collecting spreadsheets, and assembling numbers by hand. Nine sites. Six departments. Every manager seeing only their own numbers. No one seeing the full picture.

By the time anything surfaced, it was usually already affecting patients. A TAT issue at Site F might be obvious to the Site F manager, but invisible to anyone trying to make network-wide decisions. The data existed at every site. The visibility didn't exist anywhere.

Site F had both the lowest TAT percentage and the worst staffing gap (−9 people). That correlation only became visible once the data was in one place.

Why one Excel file, not a database

I chose Excel deliberately. The team doesn't have a data analyst on-site, IT support is limited, and the tool needs to survive a handover. Anything that requires a specialist to maintain is a liability in this environment.

The goal: one file, four sheets, everything computable from a filter change. Select a month, site, and department in the SELECTIONS sheet, every KPI on the DASHBOARD recalculates instantly. No macros. No code. No callbacks to me when something breaks.

In a healthcare setting where IT support is limited, robustness matters more than cleverness. Anything that requires a specialist to maintain is a liability. The best tool is the one the team can actually use forever.

What the dashboard shows

Four KPIs across the top (total tests, unique REQs, TAT % vs target, staff adequacy), then two breakdowns: performance by site and performance by department. Switch the filter, all numbers change. The connection between sites, departments, and staffing levels became visible for the first time.

Only Site C hit the 90% TAT target. The other 8 sites were consistently below, some by only 1-2%, others by 6-7%. Granularity like that requires a working multi-site aggregation system, not a phone call.
Four sheets. Each with one job. Nothing shared unnecessarily. Everything connected through formulas that respond to a single filter cell.
Sheet 1
📋 DATA ENTRY
Where raw data lives. One row per week, per site, per department: tests run, unique REQs, TAT %, staff data, analyzer status. Anyone can add rows, structure enforced by headers and column validation.
Sheet 2
⚙️ PIVOT DATA
Pre-computed organisation-level totals. Background reference layer, not filtered. Used when the DASHBOARD needs all-time values that don't change with SELECTIONS filters. Prevents formula complexity on the dashboard sheet.
Sheet 3
🎛️ SELECTIONS
The filter control panel. Change Year, Month, Week, Site, Department, that's it. Every formula on the DASHBOARD references these cells. One cell changes, everything recalculates. Zero clicks, zero macros.
Sheet 4
📊 DASHBOARD
The output layer. Four KPI cells, two tables (by site and by department), analyzer register, staffing status. Every number is a SUMIFS or AVERAGEIFS formula pulling from DATA ENTRY, filtered by SELECTIONS. Nothing is hardcoded.
1

Filtered KPIs, SUMIFS with multiple criteria

SUMIFSMulti-criteria

The total tests KPI sums only the rows matching the selected year, month, week, site, and department, simultaneously. Five criteria applied in a single formula. Change any SELECTIONS cell and the total updates instantly.

Excel formula — Total Tests (Dashboard KPI)
=SUMIFS(
    'DATA ENTRY'!F:F,         -- sum column: Tests Run
    'DATA ENTRY'!A:A, SELECTIONS!B2,  -- Year filter
    'DATA ENTRY'!B:B, SELECTIONS!B3,  -- Month filter
    'DATA ENTRY'!C:C, SELECTIONS!B4,  -- Week filter
    'DATA ENTRY'!D:D, SELECTIONS!B5,  -- Site filter
    'DATA ENTRY'!E:E, SELECTIONS!B6   -- Dept filter
)
When Site = "All Sites" and Dept = "All Departments", the wildcard (*) ensures all rows match. One formula handles both filtered and unfiltered views.
2

TAT %, AVERAGEIFS with the same logic

AVERAGEIFS

TAT % is an average, not a sum, but the same multi-criteria filter logic applies. AVERAGEIFS averages only the rows matching the current SELECTIONS. The 90% target comparison is done directly in the cell for colour-coded conditional formatting.

Excel formula — Network TAT % (Dashboard KPI)
=AVERAGEIFS(
    'DATA ENTRY'!H:H,         -- avg column: TAT %
    'DATA ENTRY'!A:A, SELECTIONS!B2,
    'DATA ENTRY'!B:B, SELECTIONS!B3,
    'DATA ENTRY'!C:C, SELECTIONS!B4,
    'DATA ENTRY'!D:D, SELECTIONS!B5,
    'DATA ENTRY'!E:E, SELECTIONS!B6
)
Conditional formatting rule: if result < 0.9 (90%), the cell highlights amber/red. If ≥ 90%, it highlights green. Visual feedback without any manual checking.
3

Site-by-site breakdown table

SUMIFSAVERAGEIFSCOUNTIFS

The site table uses the same formulas as the KPI row, but hardcodes the site name in one of the criteria, while still respecting all the other SELECTIONS filters. This means you can filter by month and get every site's numbers at once.

Excel formula — Site A row (Tests column)
=SUMIFS(
    'DATA ENTRY'!F:F,
    'DATA ENTRY'!A:A, SELECTIONS!B2,  -- Year
    'DATA ENTRY'!B:B, SELECTIONS!B3,  -- Month
    'DATA ENTRY'!C:C, SELECTIONS!B4,  -- Week
    'DATA ENTRY'!D:D, "Site A",        -- hardcoded site
    'DATA ENTRY'!E:E, SELECTIONS!B6   -- Dept filter still applies
)
Each site row locks its own name in the 4th criterion while keeping all others dynamic. Copy the formula down the table and change "Site A" to "Site B" etc. The department filter still applies across all rows.

⭐ What this revealed
Site C is the only site hitting the 90% target, and it's running with a staffing gap of −6. That means staffing alone doesn't explain TAT performance. The data opens the right questions.
Site F correlation: lowest TAT (84.8%) and the worst staffing gap (−9 people). That connection was invisible until both datasets were in one place, now it's on the dashboard every week.
Toxicology underperforms across all sites, not just at one. That's a process issue, not a site issue. A phone-call-and-spreadsheet system would never have surfaced that pattern.
Network average sits at 86.8%, 3.2 percentage points below the 90% target. The dashboard quantifies the gap. Now management has a number to report against and a breakdown to explain it.

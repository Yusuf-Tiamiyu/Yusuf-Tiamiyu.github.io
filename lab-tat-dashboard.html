The situation

Cerba Lancet Nigeria runs multiple diagnostic lab sites across Lagos. Every week, managers needed one specific answer: are we hitting the 90% TAT target? Which sites are struggling? But the answer was buried in Excel files being emailed back and forth between sites.

By the time someone stitched the spreadsheets together, the week was already gone. Slow sites stayed slow because nobody saw the pattern early enough to act. The data existed, the visibility didn't.

Before this existed: getting a network-wide view meant calling each site, collecting spreadsheets, and assembling everything manually. Every single week. No one had time. So it often didn't happen.

Why I built it the way I did

I could have built a smarter spreadsheet. But smarter spreadsheets still require someone to know how to run them. The real problem wasn't the data. The real gap was the friction between the data and the people who needed it.

So I built an upload-to-dashboard pipeline. Staff drop their weekly Excel file into the app. It gets parsed, pushed into a persistent MySQL database, and immediately surfaces as charts and KPIs anyone can see in a browser. No email chains. No waiting. No analyst in the middle.

The key design decision was making it usable by people who aren't analysts. One upload, everything updates. That constraint shaped everything, from the validation logic to how errors surface to the user.

What changed

Real-time visibility across the network. Sites below 90% TAT show up immediately, not after someone's had time to notice and report it. Lab managers can spot week-over-week trends without touching a spreadsheet. The full picture is one browser tab away, always current.

This is live in production right now. Real data. Real users. It runs on Railway with a persistent MySQL instance. Always on, no manual updates needed. That's the bar I hold myself to: build it so it runs without me.

Upload & Validate

pandasopenpyxl

Staff upload the weekly Excel report through the app. pandas reads it, validates the column structure, and rejects malformed files before anything touches the database. Bad data doesn't corrupt the historical record. It fails loudly with a clear, human-readable message.

validation snippet — Python / pandas
required_cols = ['site', 'department', 'tests_run', 'tat_pct', 'week']
missing = [c for c in required_cols if c not in df.columns]
if missing:
    raise ValueError(f"Missing columns: {missing}")
# Reject files with any row missing site or TAT data
df = df.dropna(subset=['site', 'tat_pct'])

Write to MySQL via SQLAlchemy

SQLAlchemyMySQL

Parsed rows write via SQLAlchemy. Each upload inserts new weekly records per site and department. Nothing overwrites existing data. The full history accumulates, making week-over-week trend tracking possible, not just point-in-time snapshots.

insert logic — SQLAlchemy
from sqlalchemy import create_engine
engine = create_engine(os.environ['DATABASE_URL'])
df.to_sql('weekly_tat', engine, if_exists='append', index=False)
# 'append', never overwrites; history accumulates indefinitely

Flask routes serve the dashboard

FlaskChart.js

Flask routes query the database and serve an interactive dashboard. TAT% per site vs the 90% target, week-over-week trend lines, department breakdowns, all in one view that refreshes on every upload. Deployed on Railway with zero-downtime persistence.

dashboard route — Flask
@app.route('/dashboard')
def dashboard():
    with engine.connect() as conn:
        df = pd.read_sql("""
            SELECT site, AVG(tat_pct) AS avg_tat
            FROM weekly_tat GROUP BY site
            ORDER BY avg_tat DESC
        """, conn)
    return jsonify(df.to_dict(orient='records'))
